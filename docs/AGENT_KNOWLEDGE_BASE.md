## Project Snapshot

FedRepro is a data-centric ML research system. It registers CSV evidence, creates immutable dataset versions, fingerprints versions, tracks semantic changes, profiles data, diagnoses ML readiness and leakage risk, plans interventions, generates preprocessing variants, and stores reports/AI explanations for quick rendering.

Critical invariant: AI is optional and explanation-only. AI must never compute deterministic evidence or scores.

## Current Evidence Flow

```text
Study
  -> StudyConfiguration
  -> DatasetRegistration
  -> DatasetConfiguration
  -> DatasetVersion
      -> DatasetFingerprint
      -> SemanticDiffReport for child versions
      -> DatasetProfileReport
      -> DiagnosisReport
      -> DiagnosisContract
      -> ActivityLog deterministic report payload
      -> AIGeneratedExplanation rows when AI is enabled
      -> VariantGenerationRecord when generated by Variant Generator
```

Diagnosis must work for manual versions, normal revisions, and variant-generated versions.

## Startup Warmup

`backend/app/services/evidence_warmup_service.py`

`EvidenceWarmupService.warm_all()` runs from FastAPI lifespan startup when `settings.evidence_warmup_on_startup` is true.

It scans every study and dataset version and fills:

- missing profile
- missing diagnosis
- missing semantic SCM/DSI for child versions
- stale profile/diagnosis/semantic ruleset evidence
- deterministic version report ActivityLog payload
- missing AI explanations when `AI_ENABLED=true`

AI task types warmed:

- `diagnosis_report_interpretation`
- `dataset_executive_summary`
- `dataset_explanation_report`
- `version_analysis`
- `semantic_metrics`
- `semantic_diff_interpretation`

Ollama model ranking prefers small capable local models, then uses up to 3 workers.

## Diagnosis UI Contract

Required rendered flow:

```text
Dataset Quality -> Diagnosis Metrics -> Risk Explorer -> Risk Map -> Interventions -> Human Decisions -> Variant Plan -> Evidence -> AI Explanation
```

Every compact metric/card/risk/intervention/evidence row should open the detail workspace through `openDetail()`.

The detail workspace is:

- fixed right-side panel on desktop
- bottom sheet on mobile
- not a centered modal
- raw JSON hidden under Advanced

## Variant Contract

When a generated variant is promoted:

- create synthetic registration
- create copied configuration
- generate fingerprint
- set `parent_version_id`
- set variant generation method
- write lineage
- run diagnosis
- attempt AI interpretations when enabled
- preserve VRS through `VariantGenerationRecord`

## Known Footguns

1. `WorkspacePanels.jsx` is large; search by component name and make targeted edits.
2. Do not reactivate legacy diagnosis panel implementations.
3. Backend tests must run from `backend` so `app` imports resolve.
4. `StudyService.list()` shadows the built-in `list`; keep postponed annotations in that module.
5. FastAPI route order matters for literal paths such as `/configurations/diff`.
6. `random_seed = 0` is valid protocol evidence.
7. Do not silently recompute diagnosis from the UI; use explicit run/recompute actions.
8. Do not treat missing baseline SCM/DSI as zero.
9. `ActivityLog` stores events and deterministic report payloads.
10. AI fallback content is retryable and should not be treated as a successful cached explanation.

## Safe Change Recipe For Diagnosis Work

1. Inspect backend payload shape in `datasets.py` and `ai.py`.
2. Inspect active `DiagnosisPanel`, not legacy panels.
3. Add missing click handlers through `openDetail(type, payload)`.
4. Keep compact cards visible in the default view.
5. Put deep evidence in the detail workspace.
6. Keep raw JSON in Advanced disclosures.
7. Run backend tests and frontend build.
